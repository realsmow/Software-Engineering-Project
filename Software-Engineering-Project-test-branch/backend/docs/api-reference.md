# API reference

> Generated by `npm run docs:api` from the router decorators.
> Do not edit by hand - re-run the script instead.

**4 routers, 30 procedures.**

Transport is tRPC over HTTP at `/trpc`, not REST, so there is no OpenAPI
document: the contract is the TypeScript router type, checked at compile
time on both sides. This page is the human-readable view of it.

Access is enforced by middleware on every procedure. `public` means no
session is required; everything else rejects an anonymous caller with
`NOT_AUTHENTICATED` and a wrong-role caller with `ROLE_NOT_ALLOWED`.

Notes:

- `listUsers` - `q` matches email, user ID, first name or last name.
- `createUser` - Returns the generated password once, when the caller did not supply one.
- `setUserActive` - Not implemented - AccountInfo has no enabled/disabled column.
- `setUserBan` - Recorded as a PenaltyInfo row, so the ban and its history share one table.
- `updateLendingSettings` - Rows listed are upserted; anything omitted is left alone.
- `getConfig` - Not implemented - needs a SystemConfig table; today these are env vars.
- `updateConfig` - Not implemented - see getConfig.
- `getSystemStatus` - Polled by the status page. Answers even when the database is unreachable.
- `listCronJobs` - The 8 planned jobs. All report `implemented: false` until a scheduler exists.
- `runCronJob` - Not implemented - there are no jobs to run yet.
- `listAudit` - Not implemented - needs an AuditLog table.
