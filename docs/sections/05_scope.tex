\subsubsection*{รายละเอียดความสามารถของแต่ละบทบาท}

\noindent\textbf{ผู้ใช้ / นักศึกษา (User)} — ผู้ขอยืม (ยืมได้อย่างเดียว)
\begin{itemize}
  \item ค้นหาและดูรายการอุปกรณ์ พร้อมรายละเอียดและสถานะคงเหลือ
  \item ส่งคำขอยืม โดยระบุจำนวน เลือกหมายเลขอุปกรณ์ (T2) หรือเลือกสล็อตเวลา (T3) ตามระดับอุปกรณ์
  \item ดูเครดิตของตนเอง สิทธิ์การยืม และเงื่อนไขที่เกี่ยวข้อง
  \item ติดตามสถานะคำขอ (รออนุมัติ อนุมัติ ปฏิเสธ กำลังยืม เกินกำหนด)
  \item ถ่ายรูปตอนรับและตอนคืน อัปโหลดเข้าระบบ และกดยืนยันการรับ–คืน
  \item ขอเปลี่ยนอุปกรณ์ได้ตอนรับ (เฉพาะ T1) และขอต่ออายุการยืม (ออนไลน์ หรือ นำอุปกรณ์มาให้เจ้าหน้าที่ตรวจสภาพตามรอบ)
  \item แจ้งคืน แจ้งปัญหา และรายงานความเสียหายเบื้องต้น พร้อมดูประวัติการยืมของตนเอง
  \item \emph{ข้อจำกัด:} ยืมได้อย่างเดียว ไม่มีสิทธิ์จัดการอุปกรณ์หรืออนุมัติคำขอ
\end{itemize}

\noindent\textbf{เจ้าหน้าที่ผู้ดูแล (Staff)} — ผู้ให้ยืมและดูแลอุปกรณ์
\begin{itemize}
  \item มีสิทธิ์ยืมอุปกรณ์ได้เช่นเดียวกับผู้ใช้
  \item ลงทะเบียนและจัดการบัญชีรายการอุปกรณ์ที่เปิดให้ยืม (เพิ่ม/แก้ไขรายการ จำนวน และหมายเลขประจำอุปกรณ์)
  \item จัดเตรียมและเลือกชิ้นอุปกรณ์ที่ส่งมอบ พร้อมบันทึกหมายเลข (T1, T2)
  \item บันทึกการรับ–คืน ตรวจสอบหมายเลข และยืนยันรายการ
  \item ตรวจสอบสภาพอุปกรณ์ เทียบรูปตอนรับกับตอนคืน และประเมิน/บันทึกความเสียหาย (ระดับ B0–B3)
  \item ตรวจสภาพอุปกรณ์เมื่อผู้ยืมนำมาต่ออายุตามรอบ (การต่อออนไลน์สลับกับการตรวจสภาพ)
  \item จัดการรายการเกินกำหนดและติดตามการคืน
  \item ตรวจสอบความเรียบร้อยของสถานที่/อุปกรณ์ติดที่วันละครั้ง (T3)
\end{itemize}

\noindent\textbf{อาจารย์ (Supervisor)} — ผู้อนุมัติระดับสูง
\begin{itemize}
  \item มีสิทธิ์ยืมอุปกรณ์ได้เช่นเดียวกับผู้ใช้
  \item อนุมัติหรือปฏิเสธคำขอยืมอุปกรณ์ระดับ T2 (มูลค่าสูง)
  \item อนุมัติการต่ออายุที่เกินเงื่อนไขปรกติ (เช่น การต่ออายุครั้งถัดไปของ T1 และการต่ออายุ T2)
  \item อนุมัติการยืมของผู้ที่มีเครดิตต่ำตามที่ระบบกำหนด (เช่น D2: T1, T2 และ D3: T1, T2)
  \item ใช้ดุลยพินิจในกรณีพิเศษที่ระบบไม่อนุมัติอัตโนมัติ
\end{itemize}

\noindent\textbf{ผู้ดูแลระบบ (Admin)} — ผู้ดูแลระบบโดยรวม
\begin{itemize}
  \item จัดการบัญชีผู้ใช้และกำหนดบทบาท/สิทธิ์ โดยเฉพาะการกำหนดว่าผู้ใดเป็นเจ้าหน้าที่
  \item ตั้งค่าระบบโดยรวม เช่น พารามิเตอร์ของระบบเครดิต การจัดระดับอุปกรณ์ และเงื่อนไขสิทธิ์การยืม
  \item ตรวจสอบบันทึกการใช้งานของระบบ (Audit Log)
  \item ดูแลความปลอดภัยและการควบคุมการเข้าถึงระบบ
\end{itemize}

\noindent\textit{หมายเหตุ:} ทุกบทบาทเข้าสู่ระบบด้วยบัญชีอีเมลของมหาวิทยาลัย (KU e-mail)

\noindent\textit{หมายเหตุ (ขอบเขตอำนาจ):} เจ้าหน้าที่ (Staff) และอาจารย์ (Supervisor) มีขอบเขตอำนาจตามภาควิชาหรือหน่วยงานของตนเอง ไม่สามารถอนุมัติหรือให้ยืมอุปกรณ์ข้ามภาควิชาได้ เช่น อาจารย์ภาควิชาวิศวกรรมคอมพิวเตอร์ไม่สามารถอนุมัติการยืมอุปกรณ์ของภาควิชาวิศวกรรมไฟฟ้า

\subsection{กระบวนการทำงานของระบบ (System Workflow)}

\begin{enumerate}
  \item นักศึกษาเข้าสู่ระบบ ค้นหาอุปกรณ์ และส่งคำขอยืม (ระบุรายการและช่วงเวลา)
  \item ระบบหรืออาจารย์(กรณีของระดับสูง)ประเมิณสิทธ์ในการยืมแล้วอนุมัติหรือปฏิเสธคำขอ
  \item เจ้าหน้าที่ตรวจสอบและจัดเตรียมอุปกรณ์ที่อนุมัติ พร้อมบันทึกหมายเลขประจำอุปกรณ์ (T1, T2) หรือยืนยันช่วงเวลาที่จอง (T3)
  \item เมื่ออนุมัติ นักศึกษามารับอุปกรณ์ นักเรียนกดยืนยัน เพื่อบันทึกการรับ
  \item นักศึกษาใช้งานอุปกรณ์ตามปรกติ ระบบจะแจ้งเตือนเมื่อใกล้ถึงกำหนดคืน
  \item นักศึกษาคืนอุปกรณ์ เจ้าหน้าที่ตรวจสอบสภาพและยืนยัน เพื่อบันทึกการคืน
  \item หากพบความเสียหาย เจ้าหน้าที่บันทึกรายการความเสียหาย จากนั้นปิดรายการ
\end{enumerate}

\subsection{การแบ่งระดับอุปกรณ์และกฎการยืม (Equipment Tiers \& Borrowing Rules)}
\label{subsec:tiers}

\hspace*{2em}ระบบจัดประเภทอุปกรณ์ออกเป็น 4 ระดับ (Tier) ตามมูลค่าและความเสี่ยง โดยแต่ละระดับมีขั้นตอนการอนุมัติ การส่งมอบ การตรวจความเสียหาย และการต่ออายุที่แตกต่างกัน มูลค่าเครดิตประจำอุปกรณ์แต่ละระดับเป็นมูลค่าโดยประมาณไว้เพื่อใช้คำนวณบทลงโทษในระบบเครดิต

\noindent\textbf{T0 — ยืมง่าย}\quad(ราคาต่ำกว่า 100 บาท, มูลค่าเครดิต 0 ต่อชิ้น)
\begin{itemize}
  \item \textbf{ตัวอย่าง:} สายจัมเปอร์ ตัวต้านทาน
  \item \textbf{การอนุมัติ:} ส่งคำขอยืมพร้อมจำนวน ระบบตรวจสอบสิทธิ์ (จำนวนที่ยืมได้) และของคงเหลือ แล้วอนุมัติอัตโนมัติ
  \item \textbf{ยืม–คืน:} ถ่ายรูปตอนรับและตอนคืนอุปกรณ์
  \item \textbf{ความเสียหาย:} ยอมรับตามสภาพ
  \item \textbf{การต่ออายุ:} ต่อผ่านระบบได้
\end{itemize}

\noindent\textbf{T1 — ยืมได้}\quad(ราคาไม่เกิน 1,000 บาท, มูลค่าเครดิต 5 ต่อชิ้น)
\begin{itemize}
  \item \textbf{ตัวอย่าง:} Arduino มัลติมิเตอร์
  \item \textbf{การอนุมัติ:} ยืมแบบจำกัดจำนวนชิ้น ผู้ยืมส่งคำขอ ระบบแสดงเครดิต ตรวจสอบสิทธิ์และของคงเหลือ แล้วอนุมัติอัตโนมัติ จากนั้นเจ้าหน้าที่ (staff) จัดเตรียมและเลือกชิ้นที่ส่งมอบ พร้อมบันทึกหมายเลขประจำอุปกรณ์
  \item \textbf{ยืม–คืน:} ตรวจสอบหมายเลขอุปกรณ์ ผู้ยืมกดยืนยัน และถ่ายรูปตอนรับและตอนคืน (ผู้ยืมสามารถขอเปลี่ยนอุปกรณ์ได้)
  \item \textbf{ความเสียหาย:} เจ้าหน้าที่ตรวจสอบหมายเลข เทียบรูปตอนรับกับตอนคืน และรายงานความเสียหาย (ถ้ามี) ทั้งนี้ผู้ยืมสามารถอุทธรณ์ผลการประเมินได้
  \item \textbf{การต่ออายุ:} ต่อผ่านระบบ (ออนไลน์) ได้ครั้งละ 1 ครั้ง หลังจากนั้นการต่ออายุครั้งถัดไปต้องนำอุปกรณ์มาให้เจ้าหน้าที่ตรวจสภาพก่อน จึงจะใช้งานต่อและต่อออนไลน์ได้อีก 1 ครั้ง สลับเช่นนี้ไปเรื่อยๆ (กรณีผู้ยืมมีเครดิตระดับ D2 ขึ้นไปให้ยึดตามบทในตารางบทลงโทษเครดิต)
\end{itemize}

\noindent\textbf{T2 — ยืมยาก}\quad(ราคามากกว่า 1,000 บาท, มูลค่าเครดิต 10 ต่อชิ้น)
\begin{itemize}
  \item \textbf{ตัวอย่าง:} ออสซิลโลสโคป บอร์ดราคาสูง
  \item \textbf{การอนุมัติ:} ผู้ยืมเลือกหมายเลขอุปกรณ์และส่งคำขอให้อาจารย์อนุมัติ จากนั้นเจ้าหน้าที่ (staff A) จัดเตรียมอุปกรณ์
  \item \textbf{ยืม–คืน:} ตรวจสอบหมายเลขอุปกรณ์ ผู้ยืมกดยืนยัน และถ่ายรูปตอนรับและตอนคืน
  \item \textbf{ความเสียหาย:} เจ้าหน้าที่ (staff B) ตรวจสอบหมายเลข ตรวจสภาพ และรายงานความเสียหาย (ถ้ามี) ทั้งนี้ผู้ยืมสามารถอุทธรณ์ผลการประเมินได้
  \item \textbf{การต่ออายุ:} ส่งคำขอให้อาจารย์อนุมัติ
\end{itemize}

\noindent\textbf{T3 — ของติดที่}\quad(ใช้งานภายในสถานที่ ไม่คิดมูลค่าเครดิต)
\begin{itemize}
  \item \textbf{ตัวอย่าง:} ห้องปฏิบัติการ (ห้องแลป)
  \item \textbf{การอนุมัติ:} ส่งคำขอ ดูช่วงเวลาที่ว่าง เลือกสล็อตเวลา (เป็นรายชั่วโมง) ระบบตรวจสอบสิทธิ์แล้วอนุมัติอัตโนมัติ
  \item \textbf{ยืม–คืน:} ใช้งานและคืนตามเวลาที่จอง ถ่ายรูปก่อนและหลังใช้งาน
  \item \textbf{ความเสียหาย:} เจ้าหน้าที่ตรวจสอบความเรียบร้อยวันละครั้ง
  \item \textbf{การต่ออายุ:} ตรวจสอบสล็อตเวลาและต่อเวลาผ่านระบบ
\end{itemize}

\subsubsection*{ข้อกำหนดเพิ่มเติม}
\begin{itemize}
  \item \textbf{หมายเลขประจำอุปกรณ์ (Serial Number):} ติดบนอุปกรณ์ระดับ T1–T2 เพื่อระบุแต่ละชิ้น โดยแต่ละหมายเลขจะเก็บอายุการใช้งาน ประวัติการยืม และประวัติความเสียหายที่ผ่านมา
  \item \textbf{สิทธิ์การยืม (Eligibility):} เงื่อนไขการเข้าใช้งาน เช่น ชั้นปี วิชาที่เรียน สาขาวิชา และจำนวนอุปกรณ์ที่ยืมได้
  \item \textbf{ระยะเวลาการยืม:} สูงสุด 14 วัน คืนก่อนกำหนดได้ หากต้องการยืมเกิน 14 วัน ต้องขอต่ออายุตามระดับอุปกรณ์ (Tier) และระดับเครดิต
  \item \textbf{ระยะเวลารับอุปกรณ์:} ผู้ยืมต้องมารับอุปกรณ์ภายใน 1 วันหลังจากคำขอได้รับอนุมัติ มิฉะนั้นคำขอจะถูกยกเลิกโดยอัตโนมัติ
  \item \textbf{การยืมอุปกรณ์ชิ้นเดียวกัน:} ระบบจัดการแบบ atomic ตามลำดับการส่งคำขอ (ส่งก่อนได้ก่อน) หากมีคำขอที่ขัดแย้งกัน ระบบจะยกเลิก (roll back) รายการที่ส่งช้ากว่าทั้งหมด
  \item \textbf{การยืมหลายรายการพร้อมกัน:} ผู้ยืมสามารถส่งคำขอยืมอุปกรณ์หลายชิ้นได้ในคราวเดียว โดยอุปกรณ์แต่ละชิ้นจะดำเนินไปตามกระบวนการยืมของตนเองแยกจากกัน (การอนุมัติ การจัดเตรียม การส่งมอบ และการคืน เป็นอิสระต่อกัน)
  \item \textbf{การอุทธรณ์ (Appeal):} เกิดขึ้นเมื่อผู้ยืมไม่ยอมรับผลการประเมินความเสียหายของเจ้าหน้าที่ โดยยื่นอุทธรณ์ผ่านการส่งหมายเลขประจำอุปกรณ์ รูปภาพก่อนและหลังใช้งาน ระดับการประเมินที่ได้รับ และประเด็นที่ต้องการโต้แย้ง เพื่อให้อาจารย์ตรวจสอบและตัดสิน
  \item \textbf{เครดิต (Credit):} ระดับความน่าเชื่อถือของผู้ยืม ซึ่งกำหนดสิทธิ์และเงื่อนไขการยืม (รายละเอียดในหัวข้อระบบเครดิต)
\end{itemize}

\subsection{ระบบเครดิต (Credit System)}
\label{subsec:credit}

\hspace*{2em}ระบบเครดิตใช้ประเมินความน่าเชื่อถือของผู้ยืม โดยผู้ยืมทุกคนเริ่มต้นที่คะแนนเต็ม 100 และจะถูกหักคะแนนเมื่อทำให้อุปกรณ์เสียหายหรือคืนล่าช้า ระดับเครดิตที่เหลืออยู่จะกำหนดระยะเวลาการยืม เงื่อนไขการต่ออายุ และการอนุมัติ ทั้งนี้ประวัติความเสียหายจะถูกเชื่อมโยงกับหมายเลขประจำอุปกรณ์เพื่อใช้อ้างอิงในอนาคต

\noindent\textit{หมายเหตุ:} สำหรับอุปกรณ์ที่เสียหายระดับ B3 (ชำรุดโดยสมบูรณ์ ไม่สามารถซ่อมหรือใช้งานได้อีก) เจ้าหน้าที่สามารถส่งคำขอปลดระวางอุปกรณ์ (Decommission) ให้อาจารย์พิจารณาอนุมัติได้ (ดูรายละเอียดในหัวข้อการดำเนินงานของเจ้าหน้าที่และผู้อนุมัติ)

\subsubsection*{การคำนวณบทลงโทษ (Penalty Calculation)}
\begin{itemize}
  \item \textbf{บทลงโทษจากความเสียหาย (discredit)} $=$ มูลค่าเครดิตอุปกรณ์ $\times$ มูลค่าเครดิตความเสียหาย
  \item \textbf{อายุของบทลงโทษ} (ระยะเวลาที่เครดิตถูกหัก) $=$ discredit $\times$ 2 วัน
  \item \textbf{บทลงโทษจากการคืนล่าช้า:} หักเครดิต $=$ (มูลค่าเครดิตอุปกรณ์ $\div$ 7) $\times$ จำนวนวันที่เกินกำหนด โดยการหักเครดิตมีผลตั้งแต่วันแรกที่เกินกำหนด แต่จะเริ่มนับอายุของบทลงโทษเมื่อนำอุปกรณ์มาคืนแล้ว
  \item \textbf{กรณีอุปกรณ์สูญหาย / ไม่นำมาคืน:} หากไม่นำอุปกรณ์มาคืนภายใน 2 สัปดาห์หลังหมดกำหนดยืม จะถือว่าอุปกรณ์สูญหาย และหักเครดิตเท่ากับบทลงโทษการคืนล่าช้าตามจำนวนวัน บวกกับ (มูลค่าเครดิตอุปกรณ์ $\times$ มูลค่าเครดิตความเสียหายระดับ B3)
  \begin{itemize}
    \item หากภายหลังนำอุปกรณ์มาคืน จะลดบทลงโทษเหลือการหักเครดิตตามสูตรการคืนล่าช้า บวกกับระดับความเสียหายจริงที่ประเมินได้
    \item หากไม่สามารถนำอุปกรณ์มาคืนได้จริง ผู้ยืมต้องติดต่อเจ้าหน้าที่เพื่อรายงานและรับทราบสถานการณ์ โดยอายุของบทลงโทษจะเริ่มนับตั้งแต่วันที่รายงาน
  \end{itemize}
\end{itemize}

\subsection{ขอบเขตฟังก์ชันที่จัดทำ (Scope Functions)}


\subsubsection*{Release 1 (R01) — ฟังก์ชันหลัก}

\begin{itemize}
  \item ระบบยืนยันตัวตนและจัดการสิทธิ์ตามบทบาท (Authentication \& Role-based Access)
  \item บัญชีรายการอุปกรณ์: ค้นหา กรอง ดูรายละเอียดและสถานะคงเหลือ
  \item การส่งคำขอยืมรายการเดี่ยวและหลายรายการ พร้อมระบุช่วงเวลา
  \item รอบกระบวนการการอนุมัติ/ปฏิเสธโดยระบบหรืออาจารย์
  \item การบันทึกการรับ–คืน และรายงานความเสียหายโดยเจ้าหน้าที่ผู้ดูแลอุปกรณ์
  \item การจัดการคลังอุปกรณ์แบบหลายหน่วยต่อประเภท
  \item การติดตามสถานะคำขอ: รออนุมัติ อนุมัติ ปฏิเสธ กำลังยืม คืนแล้ว และเกินกำหนด
  \item ประวัติการยืมรายบุคคล และ Dashboard พื้นฐาน
  \item การจัดระดับอุปกรณ์เป็น 4 ระดับ (T0–T3) พร้อมเงื่อนไขการอนุมัติและการส่งมอบตามระดับ
  \item การจัดการหมายเลขประจำอุปกรณ์ (Serial Number) สำหรับอุปกรณ์ระดับ T1–T2
  \item การแสดงวันที่พร้อมให้ยืม (available-from) และการจองล่วงหน้าแบบเลือกช่วงเวลา พร้อมปฏิทิน ตามเงื่อนไขการจองของแต่ละระดับอุปกรณ์
  \item ระบบเครดิตผู้ยืม: การหักคะแนนจากความเสียหายและการคืนล่าช้า อายุของบทลงโทษ และการปรับสิทธิ์การยืมตามระดับเครดิต
\end{itemize}

\subsection{การออกแบบฐานข้อมูล (Database Design)}

ระบบจัดเก็บข้อมูลด้วยฐานข้อมูลเชิงสัมพันธ์ (Relational Database) เป็นหลัก เพื่อให้การยืม การจอง และการหักคะแนนเครดิตดำเนินอยู่ภายใต้ธุรกรรม (Transaction) เดียวกันได้ การออกแบบรอบล่าสุดปรับโครงสร้างใหม่ทั้งหมดจากรอบก่อนหน้า โดยมีแนวคิดหลักสามข้อ

\begin{itemize}
  \item \textbf{รวมอุปกรณ์และห้องเป็นทรัพยากรชนิดเดียวกัน} ผ่านตาราง \texttt{ResourceInfo} ซึ่งเป็นศูนย์กลางของระบบ ตาราง \texttt{ItemIndiv} (อุปกรณ์รายชิ้น) และ \texttt{RoomInfo} (ห้องและสถานที่) ต่างผูกกลับมาที่ทรัพยากรเดียวกัน ทำให้การยืมอุปกรณ์และการจองสถานที่เดินอยู่บนกระบวนการเดียวกันทั้งหมด
  \item \textbf{แยกกฎออกจากข้อมูล} เงื่อนไขการยืมและบทลงโทษไม่ได้ฝังอยู่ในตารางอุปกรณ์ แต่ถูกแยกเป็นชุดตารางกฎ (\texttt{BorrowRule}, \texttt{BorrowConstraints}, \texttt{CreditTier}, \texttt{PenaltyRule}) ที่ปรับค่าได้โดยไม่ต้องแก้โครงสร้าง จึงเป็นกลไกที่ใช้บังคับใช้การแบ่งระดับอุปกรณ์ในหัวข้อ \ref{subsec:tiers} และระบบเครดิตในหัวข้อ \ref{subsec:credit}
  \item \textbf{เก็บทุกเหตุการณ์เป็นบันทึก (Log)} สภาพของทรัพยากร การส่งมอบและรับคืน การซ่อม และการหักคะแนน ล้วนถูกบันทึกแยกรายการพร้อมเวลาและผู้กระทำ ทำให้ตรวจสอบย้อนหลังและใช้ประกอบการอุทธรณ์ได้
\end{itemize}

\hspace*{2em}รูปที่ \ref{fig:erd} แสดงแผนภาพความสัมพันธ์ของข้อมูล (Entity–Relationship Diagram) ของทั้งระบบ และหัวข้อย่อยถัดจากนี้คือพจนานุกรมข้อมูล (Data Dictionary) ของทั้ง 33 ตาราง โดยคอลัมน์ ``คีย์'' ระบุ PK (Primary Key) หรือ FK (Foreign Key) และคีย์หลักของทุกตารางเป็น Surrogate Key ชนิด INT ที่ระบบสร้างขึ้นเอง

\subsubsection*{หมายเหตุการออกแบบ}

\begin{itemize}
  \item \textbf{ประเด็นที่ต้องตกลงร่วมกับส่วนเทคโนโลยีที่ใช้} การออกแบบรอบนี้ไม่มีฟิลด์ชนิดรายการ (LIST) เหลืออยู่เลย ตารางที่เคยเป็นเหตุผลของการเลือกใช้ MongoDB ได้แก่ \texttt{FacultyPermission}, \texttt{BorrowRule} และ \texttt{Image} ถูกแตกเป็นตารางย่อยแบบ Normalize ทั้งหมดแล้ว หัวข้อสถาปัตยกรรมระบบและเทคโนโลยีที่ใช้จึงยังคงระบุ MongoDB ไว้ตามเอกสารนำเสนอเดิม แต่ยังไม่มีข้อมูลส่วนใดในการออกแบบรอบนี้ที่ต้องจัดเก็บบน MongoDB ควรทบทวนประเด็นนี้ร่วมกันในรอบถัดไป
  \item ตาราง \texttt{ResourceInfo} และ \texttt{ConditionLog} อ้างอิงถึงกันทั้งสองทาง (\texttt{ResourceInfo.ConditionKey} ชี้ไปยัง \texttt{ConditionLog} ขณะที่ \texttt{ConditionLog.ResourceKey} ชี้กลับมายัง \texttt{ResourceInfo}) ในทางปฏิบัติจึงต้องกำหนดให้ฝั่งใดฝั่งหนึ่งรับค่า NULL ได้ในตอนสร้างระเบียนแรก หรือใช้ข้อบังคับแบบเลื่อนการตรวจสอบ (Deferred Constraint)
  \item ชื่อฟิลด์ \texttt{RoleKey} ถูกใช้กับสองความหมาย โดยใน \texttt{AccountInfo} หมายถึงบทบาทระดับระบบ (อ้างอิง \texttt{RoleInfo}) ส่วนใน \texttt{Eligibility} หมายถึงตำแหน่งภายในกลุ่ม (อ้างอิง \texttt{AuthorityRole}) ควรตั้งชื่อให้ต่างกันเพื่อลดความสับสนในการพัฒนา
  \item การตั้งชื่อฟิลด์ที่เป็น Foreign Key ยังไม่สม่ำเสมอ บางฟิลด์ลงท้ายด้วย \texttt{Key} เช่น \texttt{ManagementGroupKey} ขณะที่บางฟิลด์ไม่ลงท้าย เช่น \texttt{FacultyInfo.ManagementGroup}, \texttt{ResourceInfo.BorrowRule} และ \texttt{PenaltyRule.PenaltyType} ควรปรับให้เป็นรูปแบบเดียวกันก่อนลงมือสร้างฐานข้อมูลจริง
  \item การจัดกลุ่มในพจนานุกรมข้อมูลอ้างตามหัวข้อในเอกสารต้นทาง ยกเว้นกลุ่ม ``ทรัพยากรและสภาพ'' และ ``กฎการยืมและบทลงโทษ'' ซึ่งเอกสารต้นทางไม่ได้กำกับหัวข้อไว้ รายงานนี้จึงเพิ่มขึ้นเพื่อให้อ่านได้ต่อเนื่อง
  \item ข้อคลาดเคลื่อนเล็กน้อยในเอกสารต้นทางที่ปรับให้ถูกต้องแล้วในตารางข้างต้น ได้แก่ \texttt{UsageLog.AcocuntKey} แก้เป็น \texttt{AccountKey}, \texttt{UsageLog.CheckinTIme} แก้เป็น \texttt{CheckinTime}, \texttt{ClubInfo.ClubName} ระบุชนิดเป็น INT แก้เป็น VARCHAR เนื่องจากเก็บชื่อชมรม และ \texttt{Inspection.AppealKey} ระบุปลายทางเป็น \texttt{Appeal} แก้เป็น \texttt{AppealInfo} ตามชื่อตารางจริง ส่วนหัวข้อ ``Images'' ในเอกสารต้นทางใช้ชื่อตามแผนภาพ ERD ว่า \texttt{Image}
\end{itemize}

\subsubsection*{กลุ่มที่ 2 — เรียกเมื่อใช้งาน (Fetch \& Refetch)}

ข้อมูลที่เรียกเพียงครั้งเดียวเมื่อเปิดใช้งาน และเรียกซ้ำ (refetch) เฉพาะหลังการกระทำที่เกี่ยวข้อง แบ่งเป็นฝั่งอ่านข้อมูล (Read) และฝั่งการกระทำ (Action / Mutation)

\noindent\textbf{ฝั่งอ่านข้อมูล (Read)}
\begin{enumerate}
  \item รายการอุปกรณ์ (ค้นหา + กรอง + แบ่งหน้า)
  \item รายละเอียดอุปกรณ์รายชิ้น
  \item โปรไฟล์ตัวเอง + บทบาท (Role) + สังกัด
  \item เครดิตตัวเอง + ระดับเครดิต + รายการหักที่ยัง active
  \item รายการที่กำลังยืมอยู่ + ประวัติการยืม
  \item รายละเอียดการยืม (Loan): รูปตอนรับ และสิทธิ์ต่ออายุออนไลน์คงเหลือ
  \item สถานะและรายละเอียดการอุทธรณ์
  \item Dashboard / รายงานสถิติ (สำหรับเจ้าหน้าที่และผู้ดูแลระบบ)
  \item Master data: หมวดหมู่ ระดับอุปกรณ์ (Tier) และระดับความเสียหาย — เก็บ cache ระยะยาว (staleTime ยาว)
\end{enumerate}

\noindent\textbf{ฝั่งการกระทำ (Action / Mutation)} — เมื่อทำรายการเสร็จ ระบบจะเรียกข้อมูลที่เกี่ยวข้องซ้ำ (refetch)
\begin{itemize}
  \item ผู้ยืม: ส่งคำขอยืม, ยกเลิกคำขอ, ยืนยันรับของ + อัปโหลดรูปตอนรับ, แจ้งคืน + อัปโหลดรูปตอนคืน, ขอต่ออายุ, ยื่นอุทธรณ์
  \item เจ้าหน้าที่: จัดเตรียม/เลือกชิ้น, บันทึกรับ–คืน, ประเมินความเสียหาย, จัดการอุปกรณ์
  \item อาจารย์: อนุมัติ/ปฏิเสธคำขอ, ตัดสินอุทธรณ์
  \item ผู้ดูแลระบบ: จัดการผู้ใช้/สิทธิ์, ตั้งค่าระบบ
\end{itemize}

\subsubsection*{กลุ่มที่ 3 — งานเบื้องหลังตามเวลา (Scheduled / Cron Jobs)}

งานที่ระบบทำงานอัตโนมัติตามรอบเวลาที่ฝั่ง Backend โดยส่วนใหญ่เป็นงานรอบรายวัน

\begin{enumerate}
  \item \textbf{Mark overdue:} เลยกำหนดคืน $\rightarrow$ เปลี่ยนสถานะและหักเครดิตรายวัน
  \item \textbf{Mark lost:} เกินกำหนด 2 สัปดาห์ $\rightarrow$ ถือว่าหายและหักเครดิตเพิ่ม
  \item \textbf{หมดอายุบทลงโทษ:} ครบอายุโทษ $\rightarrow$ คืนคะแนนและอัปเดตระดับเครดิต
  \item \textbf{เตือนใกล้ครบกำหนด:} สร้าง notification และส่ง email ล่วงหน้า 1–2 วัน
  \item \textbf{คำนวณวันที่พร้อมให้ยืม:} อัปเดตวันพร้อมให้ยืมของแต่ละประเภท/ชิ้น
  \item \textbf{สร้างรอบตรวจสถานที่รายวัน (T3):} เปิด task ให้เจ้าหน้าที่ตรวจห้อง
  \item \textbf{สรุปสถิติรายวัน:} อัปเดตข้อมูล Dashboard และรายงาน
\end{enumerate}

\noindent นอกจากนี้ยังมีงานรอบรายชั่วโมง คือการยกเลิกคำขอที่หมดอายุการรับของ (คำขอที่ไม่มีผู้มารับภายในกำหนดจะถูกยกเลิกอัตโนมัติทุกชั่วโมง)
