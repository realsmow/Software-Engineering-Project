# ชุดเตรียมสาธิตระบบ (demo)

> **สาธิต 25 ก.ย. ใช้ชุดข้อมูลเยอะ `ulms_demo5` — ดูบทสาธิตทีละขั้นที่ [DEMO-FLOW.md](DEMO-FLOW.md)**
> เปิดด้วย `start_rich_demo.sh` รีเซ็ตด้วย `reset_rich_demo.sh` โค้ดอยู่ที่ `~/Projects/ulms-demo` (origin/main e0a4865)
> ส่วนที่เหลือของไฟล์นี้คือชุดเล็ก `ulms_demo3` ของรอบก่อน ยังใช้ได้เหมือนเดิม

ฐานข้อมูลสำหรับพรีเซนต์อยู่แยกจากของทุกอย่างที่มีอยู่แล้ว ชื่อ `ulms_demo3`
ไม่แตะ `app` (ฐานที่ทีมใช้), `ulms_test` / `ulms_e2e` (ของชุดทดสอบ) และ `ulms_audit` / `ulms_demo2` (ของรอบก่อน)

## เปิดระบบ

```bash
docker start postgres                                   # ถ้ายังไม่ขึ้น
cd backend  && DATABASE_URL="postgresql://postgres:postgres@localhost:5432/ulms_demo3" npm run start
cd frontend && npm run dev                              # http://localhost:5173
```

backend ต้องชี้ `ulms_demo3` ผ่าน env ตอนสั่ง ถ้าลืม จะไปใช้ `app` ตาม `backend/.env` แทน

## รีเซ็ตก่อนขึ้นเวที

รันได้ตลอด ใช้เวลาราวหนึ่งนาที ต้องเปิด backend ค้างไว้ก่อน เพราะขั้นสุดท้ายยิงผ่าน tRPC

```bash
bash docs/demo/reset_demo.sh
```

ทำสามอย่างตามลำดับ ล้างฐาน `ulms_demo3` แล้ว `prisma migrate deploy` → `npm run seed` → `docs/demo/prepare_demo_state.py`
ถ้าอยากเติมสถานะสาธิตอย่างเดียวโดยไม่ล้างฐาน สั่ง `python3 docs/demo/prepare_demo_state.py` ตรง ๆ
สคริปต์จะไม่ยอมรันซ้ำบนฐานที่มีรายการยืมอยู่แล้ว เพราะคิวจะกลายเป็นสองเท่าแทนที่จะทับของเดิม

### เปิดหลายบทบาทพร้อมกัน

คุกกี้ล็อกอินผูกกับโปรไฟล์เบราว์เซอร์ **แท็บใหม่หรือหน้าต่างใหม่ในโปรไฟล์เดียวกันคือคนเดิม**
ล็อกอินเป็นเจ้าหน้าที่ทับจะเตะผู้ยืมออกทันที เปิดสี่บทบาทพร้อมกันด้วย

```bash
bash docs/demo/open_demo_browsers.sh
```

เปิด Firefox สี่หน้าต่างคนละโปรไฟล์ (สร้างให้เองครั้งแรก) จะสั่งทีละบทบาทเองก็ได้

```bash
firefox -P ulms-staff --no-remote http://localhost:5173
```

ถ้าเอาแค่สองบทบาท **หน้าต่างปกติ + หน้าต่างส่วนตัว** ก็พอ (หน้าต่างส่วนตัวทุกบานใช้คุกกี้ร่วมกัน จึงได้เพิ่มแค่หนึ่ง)
อย่ากดออกจากระบบทุกอุปกรณ์ `auth.logoutAll` มันเตะทุกโปรไฟล์พร้อมกัน


## ของที่มีอยู่ในฐานหลังรีเซ็ต

จาก `npm run seed` คือ 2 ภาควิชา ครุภัณฑ์ 4 ชนิด รวม 15 ชิ้น และบัญชีสี่ใบข้างบน
จาก `prepare_demo_state.py` คือรายการที่ทำให้ทุกคิวมีงานค้างอย่างน้อยหนึ่งใบ

| รหัส | สถานะที่เตรียมไว้ | เห็นได้ที่ |
|---|---|---|
| L1 | ยืมออกไปแล้ว เวอร์เนีย กำหนดคืนอีก 3 วัน | ผู้ยืม "รายการที่ยืม" · เจ้าหน้าที่ onLoan |
| L2 | คำขอ T2 ออสซิลโลสโคป รออนุมัติ | คิวอนุมัติของอาจารย์ |
| L3 | อนุมัติแล้ว ยังไม่จัดเตรียม กล้อง DSLR | เจ้าหน้าที่ "รอจัดเตรียม" |
| L4 | จัดเตรียมแล้ว รอผู้ยืมมารับ สายจัมเปอร์ | เจ้าหน้าที่ "รอส่งมอบ" |
| L5 | รับคืนแล้ว รอตรวจสภาพ | เจ้าหน้าที่ "รอตรวจ" |
| L6 | ตรวจแล้วระดับ B1 หักเครดิต 1 (92 → 91) และยื่นอุทธรณ์ค้างไว้ | หน้าเครดิตของผู้ยืม · `appeal.list` |
| R1 | ห้อง 7603 (30 ที่นั่ง) จองพรุ่งนี้ 10:00–11:00 **ใบจองไปรออนุมัติที่คิวเจ้าหน้าที่** | คิวอนุมัติฝั่งเจ้าหน้าที่ · หน้าห้องของผู้ยืมยังเป็นข้อมูลจำลอง มองไม่เห็นใบนี้ |
| X1 | ขอยืมต่อ L1 (T0 + เครดิต D0) **ระบบอนุมัติอัตโนมัติ** กำหนดคืนขยับ 21 → 24 ก.ย. | หน้ารายการยืมของผู้ยืม |
| X2 | ออสซิลโลสโคป T2 ยืมออกไปแล้ว และขอยืมต่ออีก 2 วัน **รออาจารย์ตัดสิน** | คิวขอยืมต่อของอาจารย์ |

ค่าคีย์จริงของรอบล่าสุดอยู่ใน `demo-state.json` ซึ่งสคริปต์เขียนทับทุกครั้งที่รัน

## ข้อควรระวังตอนสาธิต

สิ่งที่ยังไม่ต่อกันบน `636cdca` ถ้าเดินเข้าไปกลางเวทีจะดูเหมือนระบบพัง

- **ผู้ยืมกด "ยืนยันรับของ" ไม่ได้** `loan.confirmPickup` เป็นสิทธิ์เจ้าหน้าที่ ผู้ยืมได้ 403 `ROLE_NOT_ALLOWED`
  (ส่วนอัปโหลดรูปตอนรับของใช้ได้แล้ว `image.requestUsagePhotoUpload` คืน 200) ให้ส่งมอบจากฝั่งเจ้าหน้าที่แทน
- **หน้า `/staff/handover` ยังว่าง** เป็น `PlaceholderPage` งานส่งมอบทำที่คิวเจ้าหน้าที่หน้าอื่น
- **หน้า `/reports/export` ยังว่าง** เช่นกัน
- **หน้าอุทธรณ์ของอาจารย์ยังอ่าน `MOCK_APPEALS`** อุทธรณ์ L6 ที่เตรียมไว้อยู่ในฐานจริงแต่ไม่ขึ้นบนหน้านั้น
  ถ้าจะโชว์เรื่องอุทธรณ์ ให้โชว์ผ่าน API หรือข้ามไป
- **หน้าห้องของผู้ยืมทั้งสามหน้ายังเป็นข้อมูลจำลอง** (`use-rooms.ts` คืนค่าคงที่ ปุ่มจองเขียนลง store ในเบราว์เซอร์)
  ห้อง 7603 กับใบจอง R1 อยู่ในฐานจริงและเห็นได้ที่คิวอนุมัติของเจ้าหน้าที่ แต่ไม่ขึ้นบนหน้าห้อง
- **ห้องที่ลงทะเบียนใหม่ระหว่างสาธิตจะจองไม่ได้** ไม่มี procedure ใดเปิดสิทธิ์ให้ห้อง สคริปต์เตรียมห้อง R1
  ด้วยการเขียนตาราง `Eligibility` ตรงผ่าน psql ซึ่งเขียนกำกับไว้ในสคริปต์แล้ว

## ไฟล์ในโฟลเดอร์นี้

- `prepare_demo_state.py` สร้างสถานะ L1–X1 ผ่าน tRPC ด้วยบัญชีทั้งสี่ ไม่มีการเขียนฐานตรงยกเว้นสิทธิ์ห้อง
- `reset_demo.sh` ล้างฐาน แล้วเรียก migrate + seed + สคริปต์ข้างบนต่อกันรวดเดียว
- `demo-state.json` ผลรอบล่าสุด คีย์ของแต่ละรายการและจำนวนงานในแต่ละคิว
